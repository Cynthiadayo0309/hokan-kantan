# 訪看かんたん計算

医療保険・介護保険の施設内訪問看護について、月額費用を概算するWindows向けデスクトップアプリです。

本計算結果は概算です。実際の算定・請求内容を保証するものではありません。

## 開発の背景（STAR）

### Situation（状況）

施設内の訪問看護では、サービス提供票を確認しながら、利用者ごとの訪問日、訪問回数、職種、時間帯、各種加算など、多くの条件を整理する必要があります。さらに、月額費用や利用者負担額の目安を把握するには、日ごとの内容を1か月分集計しなければなりません。

一方、現場ではITに不慣れな職員でも迷わず操作できること、インターネットに接続できない環境でも使用できることが求められていました。複雑な算定条件を手作業だけで確認すると、時間帯の判定漏れ、訪問回数の数え間違い、加算条件の見落としなどが起こりやすい状況でした。

### Task（課題）

1人の利用者について、1か月分の訪問予定と算定条件を簡単に入力し、訪問看護の月額費用総額と自己負担額の概算を確認できる仕組みを作ることを課題としました。

その際、単に金額を表示するだけでなく、次の点を重視しました。

- ITに不慣れな職員でも、入力の順序や次の操作に迷わないこと
- 時刻や訪問回数などの入力ミスを早い段階で発見できること
- 費用の内訳と計算根拠を確認できること
- オフラインで利用でき、アプリを終了しても入力内容が保持されること
- 制度改定時に、料金をソースコードの修正なしで更新できること

### Action（対策）

課題に対して、次の設計・実装を行いました。

- 操作を「月間予定を入力」「費用を確認」の2画面に整理し、日付をクリックして日別内容を登録できる構成にした
- 入力項目を原則プルダウン形式とし、上から順に選択すれば登録を完了できるようにした
- 開始・終了時刻から、訪問時間と深夜・早朝・通常・夜間の区分を自動計算した
- 時間帯またぎの内訳表示、同日の訪問時間の重複チェック、入力条件に応じた警告により、確認漏れを防ぎやすくした
- 基本療養費、管理療養費、各種加算を明細化し、月額費用総額と自己負担額の概算まで一貫して計算できるようにした
- Windows向けデスクトップアプリとして構築し、インターネット接続や利用者による開発ツールの導入を不要にした
- 入力データをPC内のSQLiteに保存し、アプリの再起動や更新後も保持できるようにした
- 料金を料金マスターとして分離し、制度改定時の更新性と、正式料金が未登録の条件を警告できる仕組みを持たせた
- 時間帯判定、訪問時間、重複判定、月間計算、データ保存などに自動テストを設けた

### Result（成果）

サービス提供票を見ながら月間予定を登録し、費用明細を確認するまでの流れを、1つのアプリ内で完結できるようになりました。職員は複雑な時間帯判定や月間集計を手作業で行う必要が減り、入力内容の誤りや確認が必要な条件にも画面上で気づきやすくなりました。

また、費用を合計額だけでなく、基本療養費・管理療養費・各種加算の明細として確認できるため、概算額の根拠を説明しやすくなりました。オフライン動作、データ保持、Windowsインストーラーによる配布にも対応し、現場のPCへ導入して継続利用できる形を実現しました。

なお、現時点では作業時間の削減率などの定量的な効果測定は行っていません。本アプリは請求額を確定するものではなく、入力・確認作業を支援する概算ツールとして位置付けています。

## 利用者向け

### インストール

配布された `訪看かんたん計算_Setup_<version>.exe` を実行し、画面の案内に従ってインストールします。インストール後はデスクトップアイコン、またはスタートメニューから起動できます。

初期版のインストーラーは未署名です。Windowsの警告が表示される場合があります。

### 使い方

1. 起動後、「医療保険」または「介護保険」を選びます。
2. 月間入力画面で、利用者名、施設名、対象年月などの条件を入力します。介護保険では認定区分と地域区分も選びます。
3. 訪問予定がある日付をクリックします。
4. 日別入力画面で訪問内容を登録します。介護保険では、看護職は開始時刻と算定区分、リハビリ職は開始時刻と20分／40分を選択でき、同じ日に複数サービスを登録できます。
5. 1か月分の入力後、「月額費用を計算」を押します。
6. 費用明細画面で、明細、単位数、月額費用総額、自己負担額の概算を確認します。
7. 必要に応じて、印刷プレビュー、印刷、PDF保存、Excel保存を使用します。

画面上部の「保険を選び直す」で切り替えても、医療・介護それぞれの入力内容は保持されます。

印刷、PDF、Excelは確認用です。請求書、レセプト、正式な請求データとしては使用しないでください。

入力内容を消す場合は、日別入力画面の「この日の内容を削除」または月間入力画面の「入力内容をすべてクリア」を使用します。削除前には確認画面が表示されます。

画面上部の「アイコン変更」から、使用権限のある画像を選ぶとアプリ用アイコンとして保存できます。反映されない場合は、アプリを再起動してください。

「標準に戻す」を押すと、保存したカスタムアイコンを使用しない状態に戻します。アプリ本体やインストーラーのアイコンは変更しません。

### データ保存場所

入力データは次の場所に保存されます。

```text
C:\Users\<ユーザー名>\AppData\Roaming\訪看かんたん計算\application.db
```

アンインストールしても、入力データが自動削除されない場合があります。

## DBとマイグレーション

SQLiteファイルはElectronの `app.getPath("userData")` 配下に保存します。起動時に保存フォルダ作成、DB作成、マイグレーション、料金マスター登録を行います。

DB構造を変更する場合は、起動時マイグレーションを追加してください。既存DBに未適用のマイグレーションを実行する前に、DBファイルのバックアップを作成します。

## 料金マスター

`resources/pricing/formal-pricing.json` を元に、2026-06-01適用開始の正式料金を登録します。既存のサンプル料金は削除せず、起動時マイグレーションで無効化します。

今回の正式対応範囲は訪問看護基本療養費（Ⅱ）です。1人区分など訪問看護基本療養費（Ⅰ）が必要な条件では、正式料金未一致として警告し、その行は合計に含めません。

料金を更新する場合は、`pricing_rules` テーブルの項目コード、項目名、区分、適用期間、職種区分、同一建物人数区分、日数範囲、回数範囲、時間帯区分、加算種別、単価、単位、端数処理、有効フラグ、サンプル料金フラグを確認してください。算定可否の条件は `eligibility_rules` と計算サービス側の判定をあわせて確認します。

介護保険の正式単位・地域単価・根拠資料は `resources/pricing/care-pricing.json` で管理します。令和6年度介護報酬改定を基本とし、2026年6月以降は選択時に令和8年6月期中改定の介護職員等処遇改善加算1.8%を適用します。料金JSONには厚生労働省資料名とURLを保存しています。制度改定時は既存ルールを上書きせず、適用開始日・終了日で版を分けてください。

高額療養費の月額上限は `resources/pricing/high-cost-care-limit-rules.json` で管理し、対象年月と所得区分から適用ルールを選びます。2026年7月以前と2026年8月～2027年7月のルールを登録しています。制度改定時は既存行を上書きせず、適用期間が重複しない新しいルールを追加してください。根拠資料は厚生労働省「高額療養費制度の見直しについて（2026年8月診療分から）」です。

## インストーラー配布時の確認

Google Driveなどでインストーラーを配布する場合は、ChromeやWindowsにより「一般的にダウンロードされていません」「開く前に信頼できることを確認してください」と表示される場合があります。

配布前に `npm.cmd run dist` を実行すると、`release/` にインストーラーとあわせて `sha256sums-<version>.txt` と `distribution-checklist-<version>.md` が作成されます。

利用者へ案内するときは、配布元、ファイル名、バージョン、SHA256を明記してください。警告を無効化する方法は案内せず、案内された配布元以外から入手したファイルは実行しないよう案内します。

詳しい配布手順とコード署名の設定方法は [docs/distribution-security.md](docs/distribution-security.md) を参照してください。
